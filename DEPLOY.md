# MIRAGE — кто, что и как

Практическая инструкция по развёртыванию поверх того, что описано в README.
Два человека, две роли, минимум того, что каждый должен знать о другом.

## Кто

- **Оператор сервера** — держит VPS/VDS с белым IP вне зоны блокировки.
  Единственный, кто знает `server_priv`. Решает, какой сайт указать в `-dest`
  (реальный TLS-сайт, на который уводятся зонды и всё, что не прошло auth).
- **Пользователь (клиент)** — сидит за блокировкой. Знает только то, что
  выдал оператор: `server_pub`, `psk`, адрес сервера. `server_priv` ему не
  нужен и не должен попадать в его руки — это не усиливает его защиту, а
  создаёт лишнюю копию секрета.

Один и тот же человек может быть в обеих ролях (свой VPS), схема не меняется.

Сервер и клиент — это роли протокола, а не платформы: сервер одинаково
работает на Ubuntu/Linux и на Windows (кода с платформенными build-тегами
в `cmdServer` нет), клиент — тоже кроссплатформенный, плюс у него есть
графическая оболочка под обе системы (см. ниже). Ниже — по одному разделу
на каждую из четырёх комбинаций «роль × ОС».

## Что нужно каждому

**Оператору:** собрать бинарник, сгенерировать пару ключей + psk, запустить
`server`, передать клиенту `server_pub` + `psk` + `host:port` — **не** по
тому каналу, который блокируется (Signal/иное E2E, не постить в открытый чат).

**Клиенту:** запустить `client` (CLI или GUI) с тем, что дал оператор,
направить приложения на локальный SOCKS5.

## Сборка

Нужен Go 1.25+ (см. `go.mod`). Собирается из корня репозитория:

```bash
git clone https://github.com/Onikore/mirage.git
cd mirage
go build -o mirage ./cmd/mirage        # Linux: сразу и CLI, и GUI (Fyne) в одном бинарнике
```

Под Windows (`mirage.exe`/`mirage-gui.exe`) можно либо кросс-компилировать
с Linux/macOS, либо собрать нативно на самой Windows (проверено на реальной
машине, Go 1.26.4) — оба пути дают идентичный результат:

```bash
# консольная версия — keygen/server/client, лог виден в cmd/PowerShell
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o mirage.exe ./cmd/mirage

# GUI-версия — без консоли позади окна, запускается двойным кликом
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-H windowsgui" -o mirage-gui.exe ./cmd/mirage
```

Windows-сборка не требует cgo/mingw (`github.com/lxn/walk` оборачивает
Win32 напрямую) — кросс-компиляция с Linux работает "из коробки". Linux
GUI (`fyne.io/fyne/v2`), наоборот, требует cgo и системные dev-заголовки —
только если собираете **на самой** Linux-машине:

```bash
sudo apt install libgl1-mesa-dev libx11-dev libxcursor-dev libxrandr-dev libxinerama-dev libxi-dev
```

Подробности (манифест Common-Controls v6, `.syso`, почему именно `rsrc`,
а не `cvtres.exe`) — в README → «Сборка».

## Сервер на Ubuntu / Linux

```bash
./mirage keygen
# server_priv: <PRIV>   — никому не отдавать
# server_pub:  <PUB>    — отдать клиенту
# psk:         <PSK>    — отдать клиенту

./mirage server -listen 0.0.0.0:8443 -priv <PRIV> -psk <PSK> -dest example.com:443
```

`-dest` — настоящий сайт, отвечающий на 443 (не обязательно связанный с
проектом). Всё, что не прошло аутентификацию (зонды, сканеры, ошибочный psk),
прозрачно уходит туда — сервер снаружи выглядит как обычный сайт.

Открыть порт в фаерволе (если `ufw` активен):

```bash
sudo ufw allow 8443/tcp
```

Держать процесс живым после отключения от SSH и переживать перезагрузки —
`systemd`. Пример юнита:

```bash
sudo tee /etc/systemd/system/mirage.service <<'EOF'
[Unit]
Description=mirage server
After=network.target

[Service]
ExecStart=/root/mirage/mirage server -listen 0.0.0.0:8443 -priv <PRIV> -psk <PSK> -dest example.com:443
Restart=always
User=root

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now mirage
sudo systemctl status mirage
```

(`screen`/`tmux` тоже подойдут для быстрого теста — выбор конкретного
способа вне охвата PoC.) Если сервер стоит не на выделенной VPS, а за
домашним роутером/NAT — нужен проброс порта на роутере (внешний `8443/tcp`
→ внутренний IP машины) и, отдельно, проверка, не прячет ли провайдер вас
за CGNAT (сравнить IP в статусе WAN роутера с тем, что видно снаружи,
например `curl ifconfig.me` с самой машины); это конфигурация вашей сети,
а не самого mirage.

## Сервер на Windows

Тот же бинарник (`mirage.exe`), та же команда, из `cmd`/PowerShell:

```powershell
.\mirage.exe keygen

.\mirage.exe server -listen 0.0.0.0:8443 -priv <PRIV> -psk <PSK> -dest example.com:443
```

Открыть порт во встроенном фаерволе (PowerShell от администратора):

```powershell
New-NetFirewallRule -DisplayName "Mirage Server" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow
```

У Windows нет прямого аналога systemd. Для быстрого теста достаточно
держать открытым окно консоли, где запущен `mirage.exe server`. Для
постоянной работы в фоне (без открытого окна, переживает выход из
сессии) — самый простой путь: обернуть в Windows-сервис через
[NSSM](https://nssm.cc/) (сторонний инструмент, не часть проекта):

```powershell
nssm install MirageServer "C:\path\to\mirage.exe" "server -listen 0.0.0.0:8443 -priv <PRIV> -psk <PSK> -dest example.com:443"
nssm start MirageServer
```

Как и на Linux — если это домашняя машина за роутером, а не VPS с белым
IP, понадобится проброс порта на роутере (см. раздел выше про Ubuntu —
логика та же, независимо от ОС сервера).

## Клиент на Ubuntu / Linux (CLI)

```bash
./mirage client -listen 127.0.0.1:1080 -server <IP оператора>:8443 -pub <PUB> -psk <PSK>
```

Дальше — обычная настройка SOCKS5 в браузере/системе на `127.0.0.1:1080`:

```bash
curl --socks5-hostname 127.0.0.1:1080 https://заблокированный-сайт/
```

По умолчанию клиент выдаёт себя за Chrome, обращающийся к `www.google.com`
(флаг `-sni`, см. ниже) — маскировка первого сообщения рукопожатия под
настоящий TLS ClientHello (см. README, uTLS). Если сессия обрывается уже
после установки (сеть моргнула, сервер перезапустили) — клиент сам
переустанавливает её с растущей паузой, перезапускать процесс не нужно
(см. README, `sessionHolder`) — но самый первый коннект при старте
по-прежнему сразу падает с ошибкой, если сервер недоступен или ключи
неверны (осознанно, чтобы опечатка была видна сразу, а не тонула в фоновых
попытках).

## Клиент на Ubuntu / Linux (GUI)

Тот же бинарник, что и CLI (`./mirage`, собран как описано выше в
разделе «Сборка»), запускается без аргументов или явно подкомандой `gui`:

```bash
./mirage gui
```

Поля: адрес сервера, публичный ключ сервера, PSK, SNI, локальный
SOCKS5-адрес; кнопка Connect/Disconnect. Введённые значения (кроме факта
подключения) запоминаются между запусками. Это тот же GUI, что и на
Windows (см. ниже) — одинаковые поля и поведение, разный тулкит под
капотом (Fyne на Linux, `lxn/walk` на Windows), потому что `lxn/walk`
оборачивает Win32 напрямую и на Linux не собирается в принципе.

## Клиент на Windows (CLI)

```powershell
.\mirage.exe client -listen 127.0.0.1:1080 -server <IP оператора>:8443 -pub <PUB> -psk <PSK>
```

Поведение идентично Linux-CLI (тот же код, кроссплатформенный):
автопереподключение после обрыва уже установленной сессии, fail-fast на
самом первом коннекте.

## Клиент на Windows (GUI)

`mirage-gui.exe` — двойной клик, без консоли позади окна. Поля те же, что
у CLI-клиента: адрес сервера, публичный ключ сервера, PSK, SNI, локальный
SOCKS5-адрес. Кнопка Connect/Disconnect запускает/останавливает тот же
SOCKS5-слушатель, что и `mirage client` — это буквально тот же код, GUI
просто дёргает его по кнопке. Введённые значения (кроме факта подключения)
запоминаются между запусками — при следующем открытии поля уже заполнены.

Проверено вживую на реальной Windows-машине (сборка, манифест
Common-Controls v6, открытие окна, полный loopback-цикл
keygen→server→client→SOCKS5→curl) — подробности в `PROGRESS.md`, запись
«Windows-манифест: GUI падал при старте». Единственное, что пока не
проверено живым кликом именно на Windows — сам сценарий автопереподключения
в GUI (обрыв сессии → статус меняется на "reconnecting" → "reconnected" без
нажатия Connect заново): логика идентична CLI и Linux-GUI, но отдельного
живого прогона на Windows для неё ещё не было.

### Флаг `-sni` (общий для CLI и GUI, обеих ОС)

```bash
./mirage client ... -sni www.wikipedia.org
```

Значение никак не проверяется сервером — это чисто косметика для пассивного
DPI, глядящего на имя хоста в ClientHello. Смысл менять его: если этот же
внешний IP оператора (или его подсеть) уже засветился под другим именем,
разумно взять что-то правдоподобное для этого IP/провайдера.

## Ротация psk без остановки сервера

Вместо `-psk <hex>` можно запустить сервер с `-psk-file <path>` — файл с
одним hex-psk на строке (`#`-комментарии и пустые строки пропускаются).
Так одновременно валидны сразу несколько ключей — старый и новый на время
перехода:

```bash
# 1. в psks.txt — только текущий (старый) psk
./mirage server -listen 0.0.0.0:8443 -priv <PRIV> -psk-file psks.txt -dest example.com:443

# 2. добавить новый psk второй строкой в psks.txt, не трогая старый,
#    и перечитать файл на живом сервере:
kill -HUP <PID сервера>
# лог: "psk-file reloaded: 2 key(s) active" — старый и новый оба работают

# 3. разослать новый psk клиентам, дать время на переход, затем убрать
#    старую строку из psks.txt и снова:
kill -HUP <PID сервера>
# лог: "psk-file reloaded: 1 key(s) active" — старый psk-клиент теперь
# отклоняется, новый продолжает работать, сервер не перезапускался
```

Битый файл при `SIGHUP` (не хватает строки, неверная длина) не обнуляет
доступ — сервер логирует ошибку и продолжает с прежним набором ключей.

`-psk` и `-psk-file` можно комбинировать (оба набора объединяются) — если
не нужна ротация, `-psk` в одиночку работает как раньше.

`SIGHUP` — сигнал POSIX; на Windows такого механизма нет, так что горячая
перезагрузка `-psk-file` там недоступна — смена ключей на Windows-сервере
требует перезапуска процесса (как и смена `-priv`).

## Что важно понимать (см. также README → «Что дальше», «Дисклеймер»)

- **Компрометация `psk` или `server_priv`** = соединения через этот сервер
  перестают быть неотличимы от вашего трафика для того, кто эти секреты
  получил. `psk` теперь можно сменить через `-psk-file` + `SIGHUP` без
  остановки сервера (только на Linux, см. выше). `server_priv` так не
  ротируется — его смена всё ещё требует перезапуска (и значит новых
  `server_pub` у всех клиентов).
- **Обе половины рукопожатия теперь замаскированы под TLS 1.3** —
  client->server под Chrome ClientHello (uTLS), server->client под
  минимальный спецификационно корректный ServerHello (см. README,
  servhello.go). Не Reality-уровня: сертификат не заимствуется у
  реального сайта, это статичный (но валидный по форме) ServerHello.
- Само рукопожатие теперь на **Noise_NKpsk0** (`flynn/noise`), не самодельное —
  ключи от старого (самодельного) `keygen` продолжают работать без переgen.
  Есть анти-replay (повтор перехваченного рукопожатия отклоняется) и per-IP
  rate-limit (burst=5, доливка 0.5/сек) — но это лимитирует именно попытки
  подключения/рукопожатия, а не число запросов внутри уже аутентифицированной
  сессии: с мультиплексом один клиент может гнать много параллельных
  запросов по одному хендшейку, и per-IP лимит их не считает по отдельности.
  Приемлемо для модели угроз «доверенный клиент с psk», не подходит как
  единственная защита от перегрузки сервера собственным же клиентом.
- **Клиент теперь делает одно рукопожатие на процесс, не на запрос**
  (см. README, mux.go). Следствия: если сервер недоступен или рукопожатие
  не проходит уже при СТАРТЕ клиента (или нажатии Connect в GUI) —
  процесс/GUI сразу сообщает об ошибке (`log.Fatal` у CLI, статус-лейбл у
  GUI), без ретраев — опечатка в адресе/ключах проявляется сразу, а не
  тонет в фоновых попытках. Если сессия обрывается посреди работы (сеть
  моргнула, сервер перезапустили) — клиент теперь сам её переустанавливает:
  растущая пауза между попытками (1с → потолок 30с), число попыток не
  ограничено (см. README, reconnect.go/`sessionHolder`); перезапускать
  `mirage client`/нажимать Connect заново не нужно. Пока переподключение
  идёт, новые локальные SOCKS5-запросы сразу отклоняются, а не встают в
  очередь и не ждут восстановления сессии.
- Это всё ещё **PoC**, не готовый боевой инструмент целиком: нет
  QUIC/shaping, `server_priv` не ротируется. Для реального использования —
  см. README, форкать sing-box/xray.
