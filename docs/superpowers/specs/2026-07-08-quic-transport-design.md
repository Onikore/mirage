# Переход на QUIC/HTTP3 транспорт — design

## Проблема

В данный момент Mirage использует TCP (и TLS-камуфляж) для транспорта, что позволяет обходить базовые блокировки. Однако TCP страдает от проблемы Head-of-Line Blocking, уязвим к активному пробингу и DPI, а также плохо переносит смену сетей клиентом (например, переход с Wi-Fi на LTE обрывает сессию).
В Roadmap (`README.md`) заявлен "QUIC/HTTP3-план. quic-go, датаграммы для UDP, стримы для TCP, connection migration. Salamander-обфускация QUIC-заголовка. Крупная, отдельная от остального работа — новый транспорт, не правка поверх текущего TCP-ядра."

## Цели

1. **Замена TCP на QUIC:** Переход от сырого TCP к `github.com/quic-go/quic-go`.
2. **Salamander-обфускация:** Маскировка QUIC-заголовков (в частности, Initial пакетов) под полностью случайный UDP-трафик или имитация других протоколов для обхода DPI, блокирующих стандартный QUIC (как в Salamander).
3. **Поддержка стримов для TCP-трафика:** Мультиплексирование, встроенное в QUIC (Streams), заменяет наш кастомный `mux.go`. SOCKS5 TCP-запросы транслируются в отдельные QUIC-стримы.
4. **Поддержка датаграмм для UDP-трафика:** QUIC Datagrams (RFC 9221) для эффективной передачи UDP-запросов (DNS, игры), не требуя TCP-подобной надежности.
5. **Connection Migration:** Нативная возможность QUIC сохранять сессию при смене IP (Wi-Fi <-> LTE) без переподключения на уровне приложения.

## Архитектура

- **`internal/transport/quic`** (новый пакет):
  - Будет инкапсулировать `quic.Config`, `quic.DialAddr`, `quic.ListenAddr`.
  - Управление обфускацией пакетов (Salamander) должно происходить на уровне `net.PacketConn`. Мы напишем обёртку над `net.UDPConn`, которая будет применять Salamander-трансформацию (например, шифрование или маскировку первых байтов/Initial пакетов) перед отправкой в сеть и снимать её при приёме. QUIC будет работать уже поверх этого обфусцированного `PacketConn`.
- **`internal/protocol`**:
  - Мультиплексирование (`mux.go`) можно будет не использовать для QUIC, так как QUIC нативно поддерживает стримы (`quic.Connection.OpenStream()`, `quic.Connection.AcceptStream()`).
  - Noise-рукопожатие: будет выполняться внутри первого QUIC-стрима (как сейчас внутри TCP-соединения). Проще всего оставить Noise поверх QUIC, чтобы не переписывать логику авторизации, rate-limit и анти-replay.
- **SOCKS5 и UDP**:
  - Поддержка SOCKS5 UDP Associate. UDP-пакеты от клиента будут упаковываться в `quic.Connection.SendMessage()` (QUIC Datagrams).
- **Схема работы**:
  `Client [SOCKS5] -> [Noise Handshake in Stream 0] -> [QUIC Streams/Datagrams] -> [Salamander Obfuscated UDP] -> Server -> [De-obfuscate] -> [QUIC] -> [Target]`

## План реализации

Работа слишком крупная для одной задачи, поэтому будет разбита на этапы:
1. **Этап 1: Базовый QUIC (без обфускации)**. Использование `quic-go` вместо `net.Conn`. Перевод клиента и сервера на UDP-транспорт с использованием нативных QUIC-стримов.
2. **Этап 2: Salamander PacketObfuscator**. Разработка обёртки над `net.PacketConn`, реализующей маскировку заголовков QUIC-пакетов, чтобы DPI не видел стандартный QUIC (маскировка Initial пакетов, рандомизация DCID/SCID).
3. **Этап 3: Поддержка UDP (Datagrams)**. Добавление обработки SOCKS5 UDP Associate и маршрутизации UDP-датаграмм через QUIC.
4. **Этап 4: Connection Migration**. Тонкая настройка `quic-go` и клиента для поддержки миграции сессий, тестирование на смене IP.

## Риски и альтернативы

- **Риск:** DPI может блокировать любой неизвестный UDP-трафик (даже обфусцированный). В этом случае QUIC не сработает.
- **Решение:** Оставить поддержку текущего TCP + TLS (uTLS) камуфляжа в качестве фоллбека. Клиент должен поддерживать оба режима и переключаться на TCP, если UDP заблокирован.
- **Риск:** Замена `mux.go` сломает текущие тесты и стабильность.
- **Решение:** Делать QUIC транспорт как отдельный независимый режим (например, флаг `-quic` при старте), не удаляя старый TCP-код.
