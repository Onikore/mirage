# Замена самодельного рукопожатия на Noise_NKpsk0 — design

## Проблема

README сам называет текущее рукопожатие «педагогическим»: ручная
последовательность HKDF-extract/expand + AES-256-GCM с nonce-счётчиком,
без внешнего аудита. Один из пунктов собственного roadmap проекта —
«Крипто-апгрейд. Заменить самодельное рукопожатие на полноценный
Noise_IKpsk2 (flynn/noise или snow)».

## Решение

`Noise_NKpsk0` через `github.com/flynn/noise`, не `IKpsk2`:

- **NK, не IK** — у клиента нет собственного статического ключа (только
  общий `psk`, как и сегодня); нет цели вводить отзываемые per-client
  идентичности в этой итерации.
- **psk0, не psk2** — проверено на реальной библиотеке: с psk2 первое
  сообщение не зависит от psk вообще, то есть любой, кто знает
  `server_pub` (без psk), получает от сервера настоящий ответ — регресс
  анти-зонд защиты. С psk0 сервер отклоняет и неверный psk, и мусорные
  байты прямо на первом сообщении, без паники — то же поведение, что и
  сейчас.
- Набор примитивов: `DH25519 + CipherAESGCM + HashSHA256` — те же
  X25519 + AES-256-GCM + SHA-256, что и сейчас.

## Совместимость (проверено)

- Формат сообщений не меняется: msg1 = 32Б эфемерный pubkey (открытым
  текстом) + 16Б AEAD-тег над пустым payload = 48Б, побайтово как
  сегодняшний `ecPub||tag1`. **`camouflage.go` не трогаем.**
- `flynn/noise`'s `DHKey{Private, Public []byte}` — тот же сырой X25519,
  что и `crypto/ecdh`. Проверено: приватный ключ, сгенерированный текущим
  `mirage keygen`, даёт одинаковый публичный ключ через оба API.
  Существующие ключи остаются рабочими без переgen.
- Направления ключей после `Split()`: `cs1` = client→server, `cs2` =
  server→client (не зависит от роли вызывающего) — совпадает с текущим
  именованием `kc2s`/`ks2c`.

## Что меняется

- `handshake.go` — переписывается вокруг `noise.HandshakeState`
  (`NewHandshakeState`, `WriteMessage`/`ReadMessage` вместо ручного
  HKDF+Seal/Open).
- `frame.go` — `secureConn` хранит `*noise.CipherState` для чтения и
  записи вместо `cipher.AEAD` + ручного `wSeq/rSeq`; Noise сам ведёт
  nonce.
- `crypto.go` — HKDF/AEAD/nonce-хелперы становятся мёртвым кодом,
  удаляются. `genKey()` заменяется на `flynn/noise`'s
  `cs.GenerateKeypair`.
- `main.go` — `cmdKeygen`, парсинг `-priv` подстраиваются под
  `noise.DHKey`; флаги и hex-формат вывода не меняются.
- **Не трогаем:** `camouflage.go`, `addr.go`, `socks.go`.

## Обработка ошибок

Контракт не меняется: `serverHandshake` на любой ошибке (не распарсился
ClientHello, `ReadMessage` вернул auth error) отдаёт `consumed` — байты,
реально прочитанные с провода — `fallback()` в `main.go` продолжает
работать без изменений.

## Тестирование

Текущий репозиторий не имел теста на само рукопожатие (только ручная
loopback-проверка). Раз переписывается крипто-ядро — добавляется
`handshake_test.go`:

1. Полный round-trip: клиент+сервер проходят рукопожатие поверх
   `net.Pipe`, обмениваются данными в обе стороны через `secureConn`.
2. Неверный psk — сервер отклоняет на первом сообщении, `consumed`
   непустой.
3. Мусорные байты — то же самое, без паники.

Плюс — ручная loopback-проверка (как в предыдущей итерации): собрать
бинарник, сгенерировать ключи, поднять сервер+клиент, прогнать легитимный
трафик, неверный psk, сырой зонд — все три сценария должны вести себя как
сегодня.
